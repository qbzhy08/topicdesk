# 主题编辑台 TopicDesk

面向主题的信息收集与高价值内容创作 Agent。

## 启动（macOS）

1. 安装 Python 3.12：到 https://www.python.org/downloads/macos/ 下载 macOS 安装包，双击安装。
2. 打开“终端”，进入解压后的目录并运行启动脚本：

```bash
cd ~/Downloads/topicdesk      # 换成你解压的位置
bash start.command
```

首次运行会自动创建虚拟环境、安装依赖（官方源失败会自动切换清华镜像），然后打开
http://127.0.0.1:8000 。之后每次只需再运行 `bash start.command`。

脚本带 `--auto-resume`：上次被中断的任务会从检查点自动继续。

### 配置 LLM（可选，后续关卡使用）

任何 OpenAI 兼容接口均可：

```bash
export LLM_BASE_URL=https://api.deepseek.com/v1
export LLM_API_KEY=sk-...
export LLM_MODEL=deepseek-chat
```

### 测试

```bash
python -m unittest discover -s tests -t .
```

## Harness 设计

```
app/harness/core.py    编排、追踪、checkpoint、预算、HITL
app/harness/runner.py  后台线程执行器，进程重启后的恢复
app/graphs/            编排图（每张图是一组节点函数）
```

- **节点**：`fn(ctx) -> 下一个节点名`。节点用 `ctx.think()` 写决策依据、`ctx.observe()` 写观察结果，
  前端时间线据此展示“已有结果怎样影响下一步”。
- **工具**：`@tool` 注册，`ctx.tool(name, **input)` 调用。每次调用记录输入、输出、耗时、成本并计入预算；
  同一任务内相同输入的成功结果会被缓存，崩溃后重跑节点不会重复抓取。
- **Checkpoint**：每个节点结束后保存 `state + usage + next_node`。节点异常、被中断或等待人工时，
  状态回滚到节点开始前的快照，避免“执行了一半”的修改被重复应用。
- **预算**：步数、工具调用次数、时长、成本。耗尽时跳到图声明的收尾节点（`on_budget`），
  输出带“结果可能不完整”标注的结果，而不是直接失败。
- **HITL**：节点调用 `ctx.human(key, ...)`，没有答复就暂停；答复写入后生成新 checkpoint（状态更新），
  从该节点继续。`rewind` 可回退到任意节点局部重跑，并指定哪些中间结果失效。
- **失败重试**：节点异常自动重试（默认 1 次）；仍失败则任务进入 failed，可手动“继续执行”。

## 固定样例回放（离线演示长期记忆）

```bash
bash start.command --replay
```

使用模拟网站和独立数据库 `data/replay.db`，不联网。演示步骤：

1. “记忆”页添加一条长期偏好（如关注重点：大海捞针）。
2. 用主题“开源大模型 长上下文 评测”跑一次检索 → 写入事实、历史交付。
3. “设置”页切到第 2 天（IT之家把 128K 更正为 64K、出现 256K 新进展、HN 不可用），再跑一次：
   召回上次记忆、只把真正的新资料标为新进展、旧结论被更正、昨天的交付标记“需更正”。
4. 在“记忆”页删除或更正一条记忆 → “下一次任务会召回什么”里不再出现。

## Memory 设计

| 层级 | 存什么 | 写入 | 召回 | 更新与遗忘 |
|---|---|---|---|---|
| 任务内 | 目标、检索历史、待核验问题、中间结果 | 每步 checkpoint | 当前任务全量 | 任务结束归档 |
| 主题长期 | 事实（验证状态、独立来源数、证据原文引句）、未解争议、历史交付 | 任务结束时抽取并合并 | 按主题，争议与需复查优先，token 预算内 | 来源更正 → 旧事实被取代、派生交付标记需更正；时效事实到期复查 |
| 用户偏好 | 阅读时间、背景、关注重点、排除内容、来源偏好、写作要求 | 仅用户确认后写入 | 按用户 + 适用范围 | 用户更正/删除；本次要求覆盖但不保存 |

- 转载只算一个独立来源；系统生成内容不算证据。
- 每条记忆记录来源、适用范围、更新时间、使用次数和完整变化记录（memory_events）。

## 中英文关键词自动翻译

- 填写主题后自动生成中文关键词和英文检索式（大模型优先，未配置时用内置术语词典），可直接修改；手动改过的栏不会被覆盖，点“⇄ 重新翻译”会以你填写的词为约束重新生成。
- 英文主题会自动补中文关键词；检索时只补缺失的语言，用户填写的优先。
- 翻译同时给出同义词/其他译法：某个检索式无结果时，自动换用备用说法再检索，过程写入任务轨迹。
- 翻译结果缓存在 `data/keyword_cache.json`，同一主题多次检索保持一致。

### 缺口补检（为什么某个子问题迟迟 0/1，以及怎么处理）

覆盖矩阵里某个子问题长期不达标，通常有三种原因：资料其实有，但用了别的说法（如 RoPE、YaRN），关键词没匹配上；
补检时把所有来源用通用词重查一遍，耗时却不针对缺口；定向检索到的结果按主题主检索式判相关度，被当成不相关过滤掉。

现在的处理：
1. **先不联网**：大模型为每个缺口补充同义词、英文术语、缩写，用已入库资料重新判断覆盖；
2. **定向检索**：仍不足的缺口，每个只发 ≤4 个检索（2 个最合适的英文源 + 2 个中文站内搜索），并行执行；结果按该缺口的检索词判断相关度，并允许超出单来源配额 3 条；
3. **限次**：每个缺口默认只补检 1 次（参数 `gap_tries`），补不上就在报告中标注“暂无足够资料”，不再重复检索；
4. 报告的“缺口补检”表列出每个缺口的结果、用时、补充的同义词和实际检索。

关键词匹配也更宽松、更准确：英文多词短语不要求相邻，短缩写按整词匹配（RAG 不会命中 average），中文长词按二元组覆盖匹配。
